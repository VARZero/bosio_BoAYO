# BoAYo와 BOSIO 창 합성

PYNQ-Z2의 실사용 경로는 `boayo_native_desktop.py`가 런처 이미지를 그려
`BosioWMClient.update_surface()`로 BOSIO 창 관리자에 전달하는 구조다.
BoAYo가 전체 정이십면체 장면을 직접 소유하지 않는다. 런처는 BOSIO의
`always_on_top` 창 하나이고, 외부 애플리케이션은 각각 자기 BOSIO 창을 만든다.

```text
외부 앱 -> BoAYo SDK: 앱 내용 + 하단 캡션 ─┐
BoAYo 런처: 캡션 없는 패널 ───────────────┤
                                        v
                 BOSIO 창 관리자: 포커스·겹침·구면 투영 AA
                                        |
                                        v
                드라이버 DDR 장면 갱신 -> BS25 캐시 -> RTL 투영 -> HDMI

GY-521 -> FPGA I²C 센서 허브 -> 96-bit AXI4-Stream -> RTL 자세 엔진
PYNQ 버튼/외부 입력 -> BOSIO 입력 이벤트 -> BoAYo 런처/SDK
```

센서 자세는 FPGA 안에서 출력 코어로 직접 전달된다. Linux가 센서 데이터를
매 프레임 읽어 화면을 그리는 경로가 아니다. 버튼과 앱 UI는 소프트웨어에서
처리한다. 창 관리자와 드라이버가 지속적인 DDR 장면 버퍼 두 개를 소유하며,
BoAYo 앱은 RGB 표면과 창 설정만 전달한다.

현재 BS25의 기본 캐시는 64바이트 라인·16KiB·2-way다. 셀 데이터는 DDR,
팔레트와 타일 디렉터리는 BRAM에 있다. BPT1 부분 갱신은 드라이버가 비활성
DDR 버퍼에 적용하고 코어가 프레임 경계에서 주소를 바꾼다. 캐시 변경으로
SDK 함수나 캡션 동작은 바뀌지 않는다.
[DDR 캐시 문서](../vendor/bosio_SphericalWM/docs/BOSIO_DDR_CACHE.md)에
버퍼 수명과 현재 보드 검증 결과가 있다.

BoAYo는 `boayo_ui.py`에서 둥근 패널, 앱 아이콘, 원형 표시와 제어 다각형의
경계를 4×4 서브픽셀 커버리지로 원래 배경색에 혼합한다. 이 작업은 640×360
RGB 표면을 만들 때 수행된다. BOSIO의 네이티브 창 합성기는 그 표면을
삼각 셀의 면적에 맞게 bilinear/적응형 4×4로 샘플링하고, 창 외곽에서는
아래 장면과 부분 커버리지로 혼합한다. 따라서 두 AA는 서로 다른 경계에
작용한다. 마지막 영상 출력 단계의 BS25 경계 AA는 BS24와 같은 필터이며
기본 혼합 강도는 32다.

런처 화면은 앱 선택, 스크롤, 표시 상태가 바뀔 때만 다시 그린다.
`boayo_native_desktop.py`도 같은 상태 키를 확인해 이미지가 바뀔 때만
`update_surface()`를 호출한다. 시선에 따른 창 위치 변경은 BOSIO의
`configure_window()`가 맡으므로 런처 표면을 다시 만들 필요가 없다.
보드에서 640×360 런처의 새 AA 첫 렌더는 약 190ms, 같은 상태의 캐시
조회는 약 0.02ms였다. 이 숫자는 RGB 표면 생성 시간이며 최종 HDMI FPS는 아니다.

BTN0과 BTN1은 유일한 런처 창을 현재 시선으로 옮겨 포커스를 주고,
BTN2는 시선 중심을 런처의 클릭 좌표로 보낸다. 앱 목록의 항목은
`apps.json`에 실제 실행 명령이 있는 경우에만 표시한다. 실행된 외부 앱은
`BosioWMClient`를 통해 별도 창을 만든다.

실행 명령으로 새 프로세스를 시작하는 데 성공하면 런처 BOSIO 창은 즉시
`mapped=False`가 된다. 런처 안에 `APPLICATION READY` 같은 전환 화면을
그리지 않는다. 새 앱 창의 준비가 잠시 걸려 검정 화면이 나와도 창은 다시
덮지 않는다. 실행 명령이 실패하면 런처를 유지한다. BTN0/BTN1은 숨긴
런처를 현재 시선에서 다시 열고, 런처가 숨겨져 있을 때 BTN2는 BOSIO
포인터를 현재 시선으로 옮겨 보이는 앱 창에 클릭 이벤트를 전달한다.

`boayo_desktop.py`와 `BoayoScene`은 호스트 미리보기 및 이전 직접 장면 경로다.
실사용 서비스는 `boayo_native_desktop.py`를 실행하므로 화질을 판단할 때는
USB3.0 Video 캡처의 실제 BOSIO 창 경로를 확인해야 한다. `M=16`과 RGB332에서는
작은 글자와 매우 가는 선에 삼각 셀 계단이 여전히 보인다.

런처의 앱 이름은 5×7 비트맵 글꼴을 4배 크기와 굵은 획으로 그린다.
오른쪽 목록 너비에 맞게 이름은 최대 9자로 표시하며, `DASHBOARD`와
`TELEMETRY`는 잘리지 않고 한 줄에 들어간다. 왼쪽 `CENTER`와 볼륨 표시는
3배 크기다. 이는 셀 수를 늘리지 않고 글자의 실제 획이 더 많은 삼각 셀에
걸치게 하려는 조정이다.

## 애플리케이션 표면과 캡션

앱 프로세스는 Bosio IPC를 통해 구면 창을 만들지만, 앱의 픽셀과 UI 캡션은 BoAYo의 `BoayoApplicationWindow`가 작성합니다. 앱은 `present(draw_content)`에 내용 그리기 함수를 넘기고, 이 클래스가 내용 영역과 아래 캡션 박스를 한 RGB24 표면으로 합칩니다. Bosio는 최종 표면의 구면 배치와 창 간 합성, 출력 코어 전송을 담당합니다. 런처 패널에는 캡션을 그리지 않습니다.

외부 앱의 공개 진입점은 `boayo_sdk.py`의 `BoayoSDK`다. SDK 한 인스턴스가 Bosio IPC 연결 하나를 유지하고 여러 앱 창의 이벤트를 창 ID별로 나눈다. 앱 내용의 포인터 이벤트는 캡션을 제외한 내용 영역 기준 픽셀 좌표로 전달된다. 런처는 앱 프로세스에 SDK 경로를 `PYTHONPATH`로 전달한다. Bosio API를 직접 호출하는 기존 앱은 계속 사용할 수 있지만 BoAYo 캡션은 SDK를 사용할 때만 그려진다.

Bosio의 창 표면 및 장치 출력 형식에는 알파 채널이 없으므로 캡션 박스는 불투명합니다. 크기 조절 버튼은 표면의 좌우 경계 안에 배치되며, 창 폭을 바꾸어도 위치가 그 폭에 맞춰 계산됩니다. 창 안의 원형 포인터는 앱 표면에 그리지 않습니다. 캡션의 닫기·이동·크기 조절은 Bosio 포인터 이벤트를 BoAYo가 처리한 뒤 Bosio 창 설정 API에 반영합니다.

BTN2는 앱 위에서 눌렀을 때 Bosio 포인터의 누름을 유지하고, 버튼이 눌린 동안 매 주기 현재 IMU 시선으로 포인터를 이동시킨다. 뗄 때 포인터 버튼을 놓는다. 마우스는 기존 Bosio evdev 포인터와 왼쪽 버튼 경로를 사용한다. 캡션이 드래그 중 포인터 아래에서 벗어나더라도 SDK는 Bosio 포인터의 월드 좌표와 버튼 상태를 확인하여 원래 창을 계속 이동·크기 조절하고, 버튼 해제 시 드래그를 정리한다. 회색 조작부는 RGB332 팔레트에서 중립 회색으로 디코드되는 입력값을 사용한다.
