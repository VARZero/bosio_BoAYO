# BoAYO M=32 증분 렌더링 적용

2026-10-17, M=32 Output Core + 투영코어 2개 구성에 BoAYO 런처와 실제
Dashboard를 적용했다. 비트스트림/RTL은 그대로이며 PS와 SDK를 수정했다.

## 변경

- 둥근 창과 분리된 손잡이의 모양을 PS coverage mask로 캐시한다. 모양 때문에
  전체 장면이 native fallback으로 넘어가지 않는다. 모양만 바꾸면 픽셀 투영은
  재사용하고 영향 타일만 재합성한다. mask는 HW 샘플 위치에서 판정하며 native
  부동소수점/투영 AA와 완전히 동일한 필터라는 의미는 아니다.
- 앱/런처/보관 카드에 SurfacePublisher를 적용했다. 첫 표면은 전체 전송하고,
  이후 실제 바뀐 픽셀의 최소 사각형만 보낸다. 같은 이미지면 IPC도 생략한다.
  전송 실패 시 이전 snapshot을 유지해 다음 호출에서 재시도한다.
- 앱의 테두리/제목/손잡이는 상태별로 캐시하며, 고정 마스크를 매번 전체
  부동소수점 영상 연산으로 적용하지 않는다. Dashboard도 표시 값이 같으면
  내용 그리기를 생략한다.
- 최소화 대기 중 축소/페이드로 전체 투영을 무효화하지 않는다. 약 0.22초 뒤
  창을 숨기고 보관 카드를 표시하며, 같은 위치로 복원하면 기존 투영을 재사용한다.
- 앱 실행은 현재 Python 실행기를 사용하며, 앱 목록은 실행 경로 또는
  BOAYO_APPS_PATH에서 읽는다. 기존 이동/크기 조절/BTN3 취소 기능은 유지한다.

## 최종 측정

640×440 픽셀, 32°×24° 시험 앱과 다른 둥근 앱/런처가 함께 있는 상태에서
8×8 내용을 변경했다. 전송 RGB는 **192 bytes** (전체 표면은 844,800 bytes),
HW 투영은 **3타일**, 최종 출력 변경은 **1타일**이었다. 다른 창은 재사용했다.

- backend 합성: 약 **22ms**
- daemon 합성+출력 전달: 약 **41ms**
- 앱 그리기+IPC: 약 **59ms**
- 앱 present 시작→출력 승인 관측: 약 **129ms**

마지막 값은 폴링/IPC 대기를 포함하고 실제 input-to-photon 측정은 아니다.
각 값은 최종 시험 한 번의 측정이며 분포나 최악 지연 보장이 아니다. 초기의
같은 범위 측정 약 781ms에서 창 테두리 캐시와 픽셀 비교 개선 후 감소했다.
새 창 생성·이동·크기 변경은 해당 창의 투영을 갱신하며, 다른 창은 캐시를
재사용한다. 모양만 바뀌면 coverage mask와 영향 타일의 합성 결과를 갱신하고
기존 픽셀 투영은 재사용한다.

실제 Dashboard는 640×440 표면, 38°×28° 창으로 표시했다. 최소화/보관 카드/
복원 동작이 통과했고 약 **59.84fps** 출력, output error 없음, fallback **0회**를
확인했다. 출력 fps는 완료된 장면을 출력하는 속도이며 앱 갱신 fps가 아니다.

## 검증 및 실행 위치

BoAYO 호스트 42개, 증분 compositor 호스트 14개 시험 통과. 실제 보드 SDK
경로 8개 사례가 통과했으며, 7개 사례에서 전체 4,220타일 캐시 재합성과
활성 DDR의 불일치가 0이었다. 실제 Dashboard에서도 전체 비교가 통과했다.

현재 보드 경로는 `/home/xilinx/bosio_boayo_m32_20261017`이며 BoAYO는 그 아래
`boayo/`에서 실행한다. WM/BoAYO 서비스는 이 경로로 연결했다. 기존 실행 경로와
서비스 설정은 보존했고, 개발 PC의 `verification/boayo_m32_before/`에 저장했다.
초기 검증에서는 `boayo-m32-dashboard.service`를 사용했다. 현재는 아래의
`boayo-desktop.service` 자동 시작 설정으로 Dashboard를 실행한다.

BTN0은 현재 시선으로 Dashboard 호출, BTN1은 앱 목록, BTN2는 클릭/드래그,
BTN3은 취소다. 기존 기본 배포 스크립트와 M=16 경로를 이번 단계에서 새 기본값으로
바꾸지는 않았다. 새 런타임을 복제할 때는 둥근 shape를 지원하는 compositor와
`boayo_surface_updates.py`를 함께 배포해야 한다.

원시 결과는 `boayo_m32_validation.json`, `boayo_live_dashboard.json`이다.
고해상도는 M=32 구면 셀 분할을 의미하며 HDMI 출력 모드를 변경한 것은 아니다.

## 부팅 시 Dashboard 자동 시작

`boayo-desktop.service`에 `BOAYO_STARTUP_DASHBOARD=1` 환경 변수를 설정하면
출력 장면과 센서가 준비된 뒤 Dashboard를 현재 시선 위치에 한 번 엽니다.
런처는 숨겨지고 BTN1로 다시 열 수 있습니다.

현재 보드에는 `/etc/systemd/system/boayo-desktop.service.d/startup.conf`를
추가했으며 WM과 데스크톱 서비스의 부팅 자동 실행을 활성화했습니다.
시작 대기 제한은 WM 준비 대기 시간보다 긴 240초입니다.

```ini
[Service]
Environment=BOAYO_STARTUP_DASHBOARD=1
TimeoutStartSec=240
```

검증된 서비스와 자동 시작 설정은 `deploy/m32/`에 보관했습니다. 서비스는
현재 보드의 배포 경로를 사용하므로, 다른 위치에 배포할 때는 경로를 맞춰야 합니다.
출력 타일의 활성 여부가 바뀔 때 하드웨어 타일 목록을 다시 읽는 OutputCore
드라이버 수정이 포함된 WM 버전을 사용합니다. 아래 최신 출력 경로도 이 수정을 유지합니다.

## 최신 캡션과 HDMI 출력 경로

활성 앱의 닫기·이동·크기 조절 버튼은 별도 4°×4° 표면으로 표시합니다.
앱 창을 확대·축소해도 캡션 버튼 크기는 유지하며, 앱 내부 콘텐츠는 기존대로
확대·축소합니다. 닫기 버튼은 같은 버튼 안에서 눌렀다 뗄 때 해당 앱만 닫습니다.
호스트 47개 테스트와 실제 보드의 버튼 크기·대상 창 닫기 검증을 통과했습니다.

고정한 최신 WM에는 HP3의 3장 화면 버퍼와 전용 VDMA가 포함됩니다. 픽셀 생성이
늦어져도 완성된 화면을 반복해 HDMI 720p60을 유지합니다. M=32와 투영 코어 2개,
변경 타일만 재투영하는 동작은 동일합니다. 보드에서 4초간 픽셀 생성을 멈춰도
화면과 60Hz 출력이 유지됐습니다. 시작 서비스는 scanout 비트스트림을 선택합니다.
[설계·실측·시작 설정](../vendor/bosio_SphericalWM/overlays/dual_projection/SCANOUT.md)을
참조하세요. 기존 기본 M=16 배포 명령은 이 별도 실행 경로로 자동 전환하지 않습니다.
